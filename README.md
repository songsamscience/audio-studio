# 송쌤과학 음원 변환 스튜디오

지정된 제작 프롬프트와 도구 사이트 디자인 시스템(V1.1)을 바탕으로 만든 주황색 작업대형 사이트입니다. 밝은/어두운 화면, 한국어 UI, 휴대폰 레이아웃을 제공합니다. v1.2부터 18가지 출력 형식(음원 16 + 영상 2)과 첫 화면의 「모든 오디오 변환」 카탈로그를 제공합니다.

## 바로 쓰기

설치 없이 인터넷 주소로 엽니다: **https://songsamscience.github.io/audio-studio/**

파일은 이 주소의 서버로 올라가지 않습니다. 사이트 파일(약 34 MB, 대부분 변환 엔진)만 처음 한 번 내려받고, 변환은 내 브라우저 안에서 합니다. 학교 PC처럼 인터넷이 불안정하면 [Releases](https://github.com/songsamscience/audio-studio/releases)의 zip을 받아 아래 「내 컴퓨터에서 실행」으로 쓰세요.

## 내 컴퓨터에서 실행

폴더 전체를 유지한 채 Python 3로 실행합니다.

```sh
python3 serve.py
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. macOS에서는 `start.command`, Windows에서는 `start.bat`을 사용할 수도 있습니다(Python 3 필요). 변환은 브라우저의 WebAssembly에서 수행하며 Python은 정적 파일만 제공합니다. 서버에 음원 업로드 엔드포인트는 없습니다.

`index.html` 더블클릭은 화면 열람용입니다. 실제 처리에는 HTTP(S)가 필요합니다. 별도 npm 설치나 빌드는 필요하지 않습니다. 공개 배포할 경우 폴더 전체를 정적 호스팅에 배치하세요. HTML·JS·CSS·폰트·Worker·WASM을 같은 출처에서 제공합니다.

> **`vendor/ffmpeg-core.wasm`(32,232,419바이트)을 꼭 함께 옮기세요.** 이 파일이 없으면 파일을 열거나 변환할 수 없습니다. 첫 화면에 「변환 엔진 파일이 없습니다」 안내가 뜨면 이 파일이 빠진 것입니다. 깃허브 웹 화면의 끌어 놓기 업로드는 25 MB가 넘는 파일을 받지 않으므로 git 명령이나 다른 방법으로 올리세요. 원본: npm `@ffmpeg/core@0.12.10`의 `dist/umd/ffmpeg-core.wasm`, SHA-256 `9F57947A5BD530D8F00C5B3F2CB2A3492FAA7E5D823315342D6A8656D0A6B7B7`.

## 사용 순서

파일 선택 → 구간 편집 → 형식·용량 선택 → 전후 듣기 → **변환하고 저장**(한 번 누르면 변환이 끝나는 대로 바로 다운로드) → 필요하면 최종 파일 듣기.

- 저장은 언제나 한 번 누르기입니다: 머리 막대·설정 칸 「변환하고 저장」, 메뉴 요약 「이대로 저장」, 녹음 「녹음 마치고 바로 저장」, 결과 카드 「MP3로도 저장」, 「원본 소리 그대로 저장」, 일괄 변환 「변환하고 저장」, 「구간별 저장」·「북마크별 파일로 저장」. 결과가 둘 이상이면 ZIP 하나로 저장합니다. 결과 카드·목록의 「다시 저장」/「저장」은 같은 파일을 한 번 더 받을 때 씁니다.

- 원본 A: 처음 불러온 파일의 수정 전 소리.
- 편집본 B: 현재 편집과 보정을 적용한 미리 듣기 소리.
- 최종 파일: 선택한 형식으로 실제 인코딩해 저장한 파일. 들을 때는 엔진이 그 파일을 다시 풀어 들려줍니다(형식과 상관없이 실제 결과 그대로).
- 파형 선택 시간은 속도·반복·크로스페이드를 적용하기 전의 편집 구간 기준입니다.
- 듣기 음량·확인용 속도·비슷한 음량 비교는 저장에 영향을 주지 않습니다. 확인용 재생 속도는 음높이도 바뀝니다.
- 이 구간 미리 듣기는 현재 선택을 따로 처리하며 반복·여백·배경음은 제외합니다. 전체 혼합 결과는 편집본 B로 확인하세요.

## 제한 및 미구현 세부 항목

- **Opus·WebM 오디오는 모노로만 저장**합니다. 포함된 코어의 libopus는 스테레오를 인코딩할 때 압축 수준 0에서도 잡음이 많은 소리·WebM 담기·60 ms 프레임 등에서 wasm 메모리 오류로 멈추는 것을 확인했습니다(`tests/engine-caps.html#set4`). 모노는 잡음·말소리·5.1 축소·5분 길이·찌그러진 소리까지 모두 통과했습니다. 스테레오가 필요하면 OGG(Vorbis)나 M4A를 쓰세요. Opus 파일을 **열어서** 다른 형식으로 바꾸는 것(입력)은 정상입니다. 샘플레이트는 48 kHz로 고정됩니다.
- 형식별 제한: AC3는 32·44.1·48 kHz와 정해진 비트레이트 단계로, MP2는 16~48 kHz(32 kHz 미만은 160 kbps 이하)로, WMA는 48 kHz 이하로 맞춰 저장하고 결과에 알립니다. M4R은 아이폰 규칙상 40초 이내여야 하며 길면 결과 카드에서 안내만 합니다(잘라 주지 않음). 8비트·32비트 float는 WAV에서만, AIFF·CAF·AU·FLAC·ALAC는 16·24비트입니다. MP3·AAC·Vorbis·Opus·WMA·MP2·영상은 최대 2채널, AC3는 6채널까지입니다.
- **영상 출력**은 브라우저 캔버스로 그린 화면(바탕색·제목·부제목·배경 그림·원본 파형 실루엣)을 PNG로 만들어 엔진에 넘깁니다. 글자 그리기(drawtext)는 코어에 글꼴 파일이 없어 쓰지 않습니다. 정지 화면은 1 fps(60초 720p 기준 약 2초), 파형 애니메이션은 6 fps(60초 720p 기준 약 9초·약 12 MB)로 단일 스레드에서 처리하므로 긴 음원은 시간이 걸립니다. 영상 길이 상한은 음원과 같은 PCM 256 MB 규칙을 따릅니다(48 kHz 스테레오 약 11분). 영상의 소리는 AAC 「fast」 코더(음원 전용 M4A는 기본 코더)로 인코딩합니다. 배경 그림은 작업 설정 JSON에 저장되지 않습니다.
- AMR·GSM은 코어에 인코더가 없어 제공하지 않습니다. 입력은 디코더가 있는 모든 형식(AMR 포함 여부는 파일마다 다름)을 받습니다.
- 모든 파일 확장자가 지원을 보장하지 않습니다. MKV/MOV/MP4 등은 내부 오디오 코덱에 따라 처리됩니다.
- **파일당 최대 4 GB**(정확히는 4 GiB — FAT32 메모리 카드 때문에 4 GiB에서 나뉜 카메라 파일도 열림)입니다. 원본은 엔진이 디스크에서 필요한 부분만 그때그때 읽습니다(WORKERFS). 작업 원본 합계 200 MB까지는 예전처럼 처음에 한 번 메모리로 복사해 원본을 옮겨도 계속 작업할 수 있고, 그보다 큰 파일은 복사하지 않으므로 작업을 마칠 때까지 원본 파일을 옮기거나 지우면 안 됩니다(지우면 「원본 파일을 읽지 못했습니다」 안내).
- **소리 길이는 스테레오 약 3시간 6분, 모노 약 6시간 12분까지**(재생용 소리 16비트·48 kHz 기준 2 GiB, 채널이 많으면 그만큼 짧아짐). 녹음도 같은 한도에서 5초를 뺀 만큼 할 수 있습니다. 넘으면 이 파일의 kHz·채널 기준 최대 길이를 알려 줍니다.
  - 긴 소리를 메모리에 펼치지 않습니다. 원본 A·편집본 B·최종 파일의 소리는 16비트 조각(Blob, 약 2.7초씩)으로 두고 재생할 부분만 몇 조각씩 풀어 이어 붙입니다(샘플 단위로 이음매 없음). 파형은 엔진이 소리를 읽으면서 만든 최댓값 표(최대 약 100만 칸, 확대용 단계표 포함)로 그립니다. 무음 찾기는 10 ms마다의 음량 표만 받습니다.
  - 변환 중의 실수(float) 작업 파일과 결과 파일은 이 사이트 전용 브라우저 저장 공간(OPFS)에 두고, 작업이 끝나면 바로 지웁니다. 3시간 스테레오면 작업 중 수 GB(작업 파일 약 4 GB + 결과)가 필요하며, 부족하면 시작 전에 「저장 공간이 부족합니다」라고 알립니다. 창을 닫거나 작업을 취소해 남은 파일은 다음에 엔진이 켜질 때 지웁니다.
  - OPFS를 쓸 수 없는 브라우저(일부 사생활 보호 창, 오래된 Safari)에서는 작업 파일이 메모리에 있어야 해서 예전 한도(스테레오 약 11분)를 그대로 씁니다.
  - 거꾸로 재생·반복·반복하는 배경음은 FFmpeg가 해당 소리를 통째로 wasm 메모리에 담아야 해서 512 MB(48 kHz 스테레오 약 23분, 모노 약 46분)까지의 길이에만 쓸 수 있습니다. 한 번의 출력은 실수 작업 파일 8 GiB까지(48 kHz 스테레오 약 6시간 12분)입니다.
  - 긴 작업은 처리 중 화면에 진행률(%)이 나옵니다. 이 Mac에서 3시간 스테레오(2 GB WAV) 실측: 열기 36~42초, MP3 192 kbps 변환 3분 46초, 「수업 녹음」 보정(잡음 감소·음량 균일화 등)을 켠 MP3 변환 12분 4초, WAV 저장 57초(모두 최종 파일 듣기 준비 포함), 편집본 B 만들기 50초, 가운데 2분만 미리 듣기 0.7초, 무음 찾기 49초. M4A(AAC)는 인코더가 느려 MP3보다 몇 배 더 걸립니다(10분 모노에 22초).
  - 디스크 여유 공간: 3시간 스테레오를 다루는 동안 브라우저 임시 공간에 약 10 GB(소리 조각 약 6 GB + 작업 파일 약 4 GB)를 씁니다. 작업이 끝나거나 창을 닫으면 정리됩니다.
  - 일괄 변환·구간별 결과 합계와 ZIP 묶음은 3 GB까지입니다(ZIP 32비트 위치 정보 한도 안쪽).
- 큰 영상의 처리 시간은 담는 형식에 따라 다릅니다. MP4·MOV(휴대폰·대부분의 카메라)는 소리 부분만 골라 읽어 4 GB라도 몇 초 만에 열립니다. MKV·WebM·MTS처럼 처음부터 끝까지 읽어야 하는 형식은 4 GB 기준 읽기만 수십 초가 걸리고, 열 때와 변환할 때마다 다시 읽습니다.
- MP3/AAC/Vorbis에서 원본 다중 채널을 유지할 수 없는 경우 스테레오로 다운믹스하고 결과에 설명합니다.
- 정규화는 -16 LUFS, -1.5 dBTP 목표의 측정 기반 처리입니다. 입력이 -50 LUFS 미만이거나 무음이면 증폭을 건너뛰고 최대 증폭을18 dB로 제한합니다. 리미터 설정은 별도의 샘플 피크 제한입니다. 화면은 실제 LUFS/true peak 수치 분석 대시보드를 제공하지 않습니다.
- 실시간 미터는 듣기 음량을 반영한 채널 RMS 기반 표시입니다. 파형 피크 표시는 원본의 샘플 피크이며 true peak가 아닙니다.
- A/B 시간이 일대일로 연결되지 않는 믹싱·크로스페이드 구간은 처음부터 개별 비교합니다.
- 비트레이트별 짧은 실제 인코딩 비교 전용 기능은 없습니다. 선택 구간을 남긴 뒤 해당 설정으로 변환하여 최종 파일을 비교하세요.
- 구간별 내보내기는 보정·속도만 적용하며 전체 믹스·반복·여백은 제외합니다.
- 일괄 변환·구간별 결과는 끝나면 하나면 그 파일로, 둘 이상이면 ZIP 하나로 바로 저장하고, 목록에서 하나씩 다시 저장할 수도 있습니다. ZIP은 압축하지 않고 묶기만 하며(음원은 이미 압축됨), 파일 이름은 UTF-8로 기록합니다. 묶을 결과 합계가 3 GB를 넘으면 하나씩 저장하도록 안내하고, 200 MB가 넘으면 묶는 동안 처리 화면을 띄웁니다.
- OGG(Vorbis)는 비트레이트 대신 음질 단계(2·4·6·8)를 고릅니다. Vorbis는 샘플레이트·채널마다 허용 비트레이트가 달라 고정 비트레이트 지정이 모노·저샘플레이트 원본에서 실패하기 때문입니다. 화면의 kbps는 44.1 kHz 스테레오 기준 대략값입니다.
- 원본 샘플레이트가 32 kHz 미만(예: 16·22.05 kHz 녹음)이고 MP3를 192 kbps 이상으로 저장할 때, 샘플레이트가 「원본 유지」이면 44.1 kHz로 저장하고 결과에 알립니다. 22.05 kHz를 직접 고르면 MP3 비트레이트는 160 kbps까지만 고를 수 있습니다.
- 거꾸로 재생을 켜면 원본 A와 편집본 B의 시간을 일대일로 맞출 수 없어 처음부터 비교합니다(믹싱과 같음). 채널 처리는 2채널 이상 원본에만 적용되고 다운믹스 전에 처리됩니다.
- 사용자 보정 프리셋은 효과 값만 저장합니다. 전체 편집은 프로젝트 JSON으로 내보내세요. 작업 이력 자체는 JSON에 저장하지 않습니다. 마지막 출력 설정(형식·비트레이트·영상 크기 등, 제목·제작자 태그 제외)은 `localStorage`의 `ss.audio.output`에 기억합니다.
- 프로젝트는 현재 불러온 원본들과 파일명·크기·길이 등으로 비교해 연결합니다. 원본 바이트를 포함하지 않고 해시 기반 재연결은 제공하지 않습니다. 연결이 거부되면 올바른 원본을 다시 선택하세요.
- 원본 커버 이미지는 유지/편집하지 않습니다. 메타데이터 유지 모드는 첫 원본의 텍스트 태그만 대상입니다.
- 브라우저 강제 종료 복구·클라우드 저장·전사·AI 복원은 제공하지 않습니다.
- 2026-10-05 v1.1에서 Windows 11 + Chromium 계열 브라우저로 주요 기능을, v1.2에서 macOS + Claude 앱 내장 브라우저(Chromium)로 새 형식 18가지·영상·채널·역재생을 실제 파일로 검증했습니다(`docs/검증결과.md`). Edge·Firefox·Safari·Android·iOS와 실제 마이크 녹음은 아직 검증하지 않았습니다.

## 단계별 상태

1단계 핵심 변환·추출·편집·3종 재생·저장 흐름을 구현했습니다.
2단계 보정·연결·크로스페이드·취소·실행 취소를 구현했습니다.
3단계 수업 구간·녹음·일괄 변환·태그·설정 저장을 구현했으며 ZIP 음원 묶음·커버·북마크 이름 수정 등은 위 제한을 따릅니다.
4단계 2트랙·덕킹·저장 속도/피치·오프라인 자원을 구현했으며 장치별 호환성 및 최종 통합 검증은 완료 항목으로 표시하지 않습니다.

## 변경 이력

### v1.4.1 (2026-10-07) — 저장은 한 번 누르기로

사용자 요청: 녹음 파일을 저장할 때 단추를 두 번 눌러야 해서 당황스럽다. 다른 메뉴도 저장까지 한 번에 되도록 줄이기.
- 원인: 「변환·내보내기」·「변환하고 결과 확인」·「이대로 변환」은 변환만 하고, 결과 카드의 「다운로드」를 한 번 더 눌러야 파일이 생겼습니다. 녹음은 「녹음 마치고 편집」 → 변환 → 다운로드로 세 번이었습니다.
- 변환 단추는 이제 변환이 끝나는 대로 파일을 바로 내려받습니다. 이름도 「변환하고 저장」(머리 막대·설정 칸, 영상이면 설정 칸은 「영상으로 만들어 저장」) · 「이대로 저장」(메뉴 요약)으로 바꿨습니다. 결과 카드는 「변환하고 저장했어요」와 다운로드 목록 안내를 보여 주고, 「다운로드」는 「다시 저장」(같은 파일 한 번 더)이 됐습니다. 설정이 바뀐 결과 카드에는 「변환하고 저장」을 바로 둡니다.
- 녹음: 녹음 중에 **「녹음 마치고 바로 저장 · MP3」**(지금 음원 형식, 영상 설정이면 MP3)를 누르면 한 번에 파일이 됩니다. 「녹음 마치고 편집」으로 열면 메뉴를 접고 「이대로 저장」 요약을 보여 줍니다. 녹음 파일 이름은 `수업_녹음_YYYY-MM-DD_HHMM`(뒤에 `_변환`을 붙이지 않음). 바로 저장하려던 녹음을 열지 못하면 녹음 원본(WebM 등)을 그대로 저장합니다. 저장하지 않은 녹음이 있을 때 새로 녹음하면 「이전 녹음 저장하고 새로 녹음」 한 번으로 저장과 새 녹음이 함께 됩니다.
- 결과 카드 「MP3로도 저장」은 형식만 바꾸고 「변환을 다시 눌러 주세요」라고 하던 것을 바로 변환·저장으로 고쳤습니다. 「원본 소리 그대로」(재인코딩 없이)는 확인 창 없이 바로 저장합니다(설명은 메뉴 카드·설정 칸·결과 카드에 있음).
- 일괄 변환: 「변환하고 저장」(이어서 할 때 「남은 파일 변환하고 저장」). 모두 끝나면 아직 저장하지 않은 결과를 하나면 그 파일로, 둘 이상이면 ZIP 하나로 바로 저장합니다(파일 여러 개를 따로 내려받으면 Chrome이 「여러 파일 다운로드」 허용을 물으므로 ZIP 하나로). 작업 취소로 멈추거나 3 GB를 넘으면 자동 저장하지 않고 각 줄 「저장」·ZIP 단추를 씁니다.
- 「구간별 저장」·「북마크별 파일로 저장」: 하나면 창 없이 그 파일을, 둘 이상이면 ZIP 하나를 바로 저장하고, 하나씩 다시 받을 수 있는 목록 창을 보여 줍니다. 모든 구간을 다 만들었을 때만 저장합니다 — 「작업 취소」면 아무것도 저장하지 않고, 중간에 오류가 나면 만든 구간만 목록으로 보여 줍니다(자동 저장 안 함).
- 일괄 변환 목록은 저장한 뒤 줄마다 「저장함」·「다시 저장」, 「ZIP 다시 저장」, 위에 저장 안내를 보여 주고, 더 변환할 것이 없으면 주 버튼을 「모두 변환했어요」로 끕니다. 200 MB가 넘는 ZIP은 처리 화면 뒤에서 묶어 다른 저장이 끼어들지 않게 했습니다. ZIP 이름에 시각을 넣었습니다(`일괄변환_YYYY-MM-DD_HHMM.zip`).
- 녹음을 잃지 않게: 녹음을 편집 화면으로 열었거나 바로 저장이 실패·취소되면 파일로 저장할 때까지 창 닫기 경고를 켜 둡니다. 그 위에 새로 녹음하거나 다른 파일을 열면 「지금 녹음 저장하고 새로 녹음」·「녹음 먼저 저장」을 묻습니다(한 번에 저장). 길이 한도에 닿거나 녹음 장치 오류로 멈춘 녹음은 버리지 않고 바로 저장합니다. 바로 저장 중 변환이 실패하면 녹음 원본을 그대로 저장하고, 파일 분석을 「작업 취소」하면 내려받지 않고 「녹음 파일 저장」으로 보관합니다. 녹음 원본을 저장한 뒤에도 다음 녹음 전까지 「녹음 파일 다시 저장」을 둡니다. 영상 설정에서 바로 저장하면 이번만 MP3로 저장하고 기억된 설정은 그대로 둡니다.
- 결과 카드: 저장한 뒤 파일 이름을 바꾸면 「이름을 바꿨어요」와 강조된 「새 이름으로 저장」을 보여 줍니다. 설정이 그대로인데 다시 「변환하고 저장」을 누르면 다시 변환하지 않고 같은 파일을 바로 내려주고, 1.5초 안에 두 번 누른 것은 한 번으로 칩니다. 원본 소리 그대로 저장은 「원본 그대로 저장했어요」로 알립니다. 저장 뒤 키보드 포커스는 결과 제목으로 옮깁니다.
- **Ctrl/Cmd+S**는 웹 페이지 대신 소리를 저장합니다(녹음 중이면 마치고 바로 저장). 긴 안내는 길이에 맞춰 더 오래 보여 줍니다(최대 12초). Safari 첫 다운로드 허용 질문에 답할 수 있게 다운로드 주소를 5분 유지합니다. 도움말에 저장 방법·Safari·앱 안 브라우저 안내를 넣었습니다.
- 그대로 둔 것: 작업 설정 창(저장·불러오기를 고르는 갈림길이고 원본 파일명이 들어간다는 설명이 필요), 보정 프리셋 저장 창(이름을 정해야 함, 단추 이름은 「프리셋으로 저장」으로 분명히), 메뉴 카드는 고르기만 함(세부 값·파일 이름을 바꿀 기회), 「영상으로 만들기」는 제목·바탕색을 정한 뒤 저장.
- 검증: 전체 기능 점검 21/21(`tests/app-smoke.js`, 변환 한 번에 저장이 정확히 한 번 일어나는지·원본 그대로·북마크 ZIP·일괄 ZIP을 확인하도록 고침) · 회귀 점검 29/29(`tests/app-regression.js`, 새 점검 R19~R29: 녹음 바로 저장, 머리 막대·이대로 저장·다시 저장·영상·MP3로도 저장, 열지 못한 녹음 원본 저장, 이전 녹음 저장하고 새로 녹음, 일괄 1개는 ZIP 없이·저장 표시·주 버튼 끄기, 구간 1개는 창 없이, 구간 저장 취소는 저장 0건, 이름 바꾼 뒤 새 이름으로 저장·같은 결과 다시 변환 안 함·두 번 눌러도 한 번, 저장 안 한 녹음 위 새 녹음·다른 파일 열기 확인, Ctrl/Cmd+S, 분석 취소 때 원본 보관). 375·320 px·어두운 화면에서 녹음 단추·결과 카드가 넘치지 않음. 코드·문구·브라우저 다운로드 규칙 감사와 독립 검토(에이전트)에서 나온 문제를 고친 뒤 다시 돌린 결과입니다. 점검 스크립트는 실제 다운로드 폴더에 쓰지 않고 저장 요청(파일 이름)만 기록합니다. `sw.js` VERSION v1.4.1. 백업 `archive-v1.4.0/`.

### v1.4.0 (2026-10-05) — 소리 길이 약 3시간(모노 6시간)까지

사용자 요청: 길이 제한과 녹음 시간 제한을 할 수 있는 만큼 늘리기.
- 한도: 스테레오 약 11분 → **약 3시간 6분**, 모노 약 22분 → **약 6시간 12분**(48 kHz 기준). 녹음도 같은 한도(모노 녹음이면 약 6시간 12분)까지, 녹음 데이터 상한은 100 MB → 2 GB.
- 왜 11분이었나: 열 때 소리 전체를 실수(float)로 펼친 AudioBuffer를 원본 A·편집본 B·최종 파일마다 하나씩 메모리에 들고 있었고(3시간이면 하나에 2 GB), 변환 중의 실수 작업 파일도 메모리(MEMFS)에 있었습니다.
- 바꾼 구조: ① 엔진이 소리를 풀면서 16비트 조각(Blob)·파형 최댓값 표·무음용 10 ms 음량 표를 바로 만들어 넘깁니다(`pcmSink`). ② 재생은 조각을 약 8초 앞까지 이어서 예약하는 방식으로 바꿨습니다(샘플 단위 이음매, 선택 끝에서 소리가 직접 멈추는 동작 유지). ③ 변환 중의 작업 파일·결과 파일은 OPFS(이 사이트 전용 브라우저 저장 공간)의 동기 파일에 두고 끝나면 지웁니다. 결과는 Blob으로 넘겨 다운로드·ZIP도 메모리에 모으지 않습니다. ④ OPFS가 없으면 예전 한도로 동작합니다.
- 긴 작업에 진행률(%)을 표시하고, 1시간 이상은 시간을 `1:23:45.678`처럼 보여 줍니다. 파형은 최댓값 단계표로 그려 어느 배율에서도 빠르고, 긴 소리는 약 5초가 화면을 채울 때까지 확대할 수 있습니다.

### v1.3.0 (2026-10-05) — 파일당 4 GB까지

## 개인정보·오프라인

파일과 결과, 원본 파일명·메타데이터는 외부 서비스로 전송하지 않습니다. 외부 API·분석 스크립트·CDN 실행 의존성을 사용하지 않습니다. 로컬스토리지는 테마(`ss.theme`), 직접 저장한 보정 프리셋(`ss.audio.presets`), 마지막 출력 설정(`ss.audio.output`, 제목·제작자 등 내용 태그 제외)만 보관합니다. 원본과 결과, 영상 배경 그림은 메모리(브라우저가 관리하는 임시 Blob 포함)에서 다루며 IndexedDB/서비스 워커 캐시에 저장하지 않습니다. 긴 변환의 작업 파일만 작업하는 동안 OPFS(`audio-studio-scratch` 폴더)에 두었다가 끝나면 지우고, 남은 것은 다음 실행 때 지웁니다. 이 파일도 기기 밖으로 나가지 않습니다.

도움말의 ‘오프라인 사용 준비’로 정적 실행 자원을 캐시합니다. 모든 자원이 준비된 뒤에만 완료를 표시합니다. 브라우저 캐시 삭제/용량 제한에 따라 다시 준비해야 할 수 있습니다. 자동 업데이트로 작업을 강제 새로고침하지 않습니다. ‘앱 자원 캐시 지우기’는 프로그램 캐시를, ‘작업 데이터 지우기’는 현재 메모리 작업을 정리합니다. 이미 다운로드한 파일을 삭제하거나 기기의 메모리를 보안 소거하는 기능은 아닙니다.

## 개발 구조

- `index.html`, `style.css`, `theme.js`: 화면·주황색 디자인 토큰·테마.
- `app.js`: UI, 재생, 파형, 작업 연결, 녹음·일괄·프로젝트.
- `model.js`: 비파괴 편집 상태, 이력, 시간 매핑, JSON 스키마.
- `engine.js`: 순차 작업 큐, Worker 수명·취소, 원본 재연결, 재생용 소리 조각(`PcmTrack`).
- `engine-worker.js`: FFmpeg 필터 그래프·분석·인코딩, OPFS 작업 파일, 소리를 조각·파형·음량 표로 내보내는 출력.
- `vendor/`: 고정 엔진·WASM·글꼴·라이선스.
- `sw.js`: 정적 자원만 캐시하는 오프라인 보조 기능.
- `serve.py`: 업로드 기능 없는 정적 파일 서버.
- `tests/engine-caps.html` + `engine-caps.js` + `engine-caps-worker.js`: 번들 코어가 실제로 지원하는 인코더·먹서·필터 목록과 후보 형식의 실제 인코딩 시험(개발용, `#set2` `#set3`로 다른 시험 묶음). 새 형식을 추가하기 전에 여기서 먼저 확인하세요.
- `tests/engine-suite.js`: 실제 Worker·WASM 엔진 점검(18가지 형식 인코딩·재디코딩, 영상, 거꾸로·채널·속도·음높이, 오류 복구, 취소 후 재연결, 편집본 B·무음 표, OPFS 작업 파일 정리 등 32개). `tests/engine-runner.html`을 열고 콘솔에서 `await runEngineSuite(fetchFixture)`(Playwright가 있으면 `tests/browser-engine.cjs`). 같은 출처에서 앱을 쓴 적이 있으면 로컬스토리지 항목 때문에 마지막 「자동 저장 없음」만 실패로 나옵니다.
- `tests/app-smoke.js` · `tests/app-regression.js`: 앱 화면을 실제로 눌러 보는 전체 점검(21개)과 회귀 점검(18개). 실행 중인 앱 페이지에서 `tests/app-smoke.js`를 불러온 뒤 개발자 도구 콘솔에서 `await runSmoke()` 또는 `await runRegression()`.
- `tests/model-test.cjs`: 편집 모델·엔진 그래프·인코더 옵션 테스트. Node.js가 있으면 `node tests/model-test.cjs`, 없으면 사이트 폴더에서 `python -m http.server 8852 --bind 127.0.0.1`을 실행하고 `http://127.0.0.1:8852/tests/model-test.html`을 엽니다(serve.py의 CSP는 테스트 실행을 막습니다). 제목이 PASS면 통과입니다.
- `archive-v*/`: 각 판 수정 전 원본 백업(배포·저장소에는 필요 없음).
- `docs/영상만들기_예시/`: 실제 앱으로 만든 영상 예시 3개(정지 화면 · 파형 애니메이션 · 세로 쇼츠)와 프레임 그림, 한눈에 보기(`0_영상만들기_한눈에.png`). 배포에는 필요 없음.

효과를 추가하려면 model.js 기본값·검증/직렬화, engine-worker.js 필터·실제 지원 목록, app.js 설정 화면을 함께 확장합니다. 미리 듣기와 최종 출력 모두 공통 그래프를 사용합니다. 출력 형식을 추가할 때는 engine-worker.js `FORMATS`(인코더·먹서·MIME·확장자·kind), `formatOptions`(코덱별 샘플레이트·비트레이트·채널 규칙), model.js `OUTPUT_FORMATS`·`estimateBytes`, app.js `FORMAT_INFO`(이름·설명·갈래·선택지)와 카탈로그 `PAIRS`를 함께 정의하고, `tests/engine-caps.html`로 실제 인코딩을 먼저 확인하세요. 지원하지 않는 항목을 활성화하지 마세요. 출력 설정이나 효과를 바꾸면 결과 버전을 무효화해야 합니다.

## 호스팅 설정

Worker/JS MIME은 `text/javascript`, WASM은 `application/wasm`, WOFF2는 `font/woff2`로 제공합니다. HTTPS를 사용하면 마이크와 서비스 워커를 사용할 수 있습니다. 현재 단일 스레드 엔진은 SharedArrayBuffer 및 COOP/COEP가 필수가 아닙니다. 향후 다중 스레드를 추가할 경우 `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`와 `crossOriginIsolated`를 확인해야 합니다.

CSP 예시는 serve.py에 포함되어 있습니다. script-src에는 self 및 wasm-unsafe-eval, worker-src에는 self/blob, media-src에는 self/blob가 필요합니다. 앱 수정 시 sw.js의 VERSION을 갱신해 엔진·앱 버전이 섞이지 않게 유지하세요.
