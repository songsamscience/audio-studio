# 송쌤과학 음원 변환 스튜디오

지정된 제작 프롬프트와 도구 사이트 디자인 시스템(V1.1)을 바탕으로 만든 주황색 작업대형 사이트입니다. 밝은/어두운 화면, 한국어 UI, 휴대폰 레이아웃을 제공합니다. v1.2부터 18가지 출력 형식(음원 16 + 영상 2)과 첫 화면의 「모든 오디오 변환」 카탈로그를 제공합니다.

## 바로 쓰기

설치 없이 인터넷 주소로 엽니다: **https://songsamscience.github.io/audio-studio/**

파일은 이 주소의 서버로 올라가지 않습니다. 사이트 파일(약 34 MB, 대부분 변환 엔진)만 처음 한 번 내려받고, 변환은 내 브라우저 안에서 합니다. 학교 PC처럼 인터넷이 불안정하면 [Releases](https://github.com/songsamscience/audio-studio/releases)의 zip을 받아 아래 「내 컴퓨터에서 실행」으로 쓰세요.

## 내 컴퓨터에서 실행

폴더 전체를 유지한 채 Python 3로 실행합니다.

```sh
python3 serve.py
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. macOS에서는 `start.command`, Windows에서는 `start.bat`을 사용할 수도 있습니다(Python 3 필요). 변환은 브라우저의 WebAssembly에서 수행하며 Python은 정적 파일만 제공합니다. 서버에 음원 업로드 엔드포인트는 없습니다.

`index.html` 더블클릭은 화면 열람용입니다. 실제 처리에는 HTTP(S)가 필요합니다. 별도 npm 설치나 빌드는 필요하지 않습니다. 공개 배포할 경우 폴더 전체를 정적 호스팅에 배치하세요. HTML·JS·CSS·폰트·Worker·WASM을 같은 출처에서 제공합니다.

> **`vendor/ffmpeg-core.wasm`(32,232,419바이트)을 꼭 함께 옮기세요.** 이 파일이 없으면 파일을 열거나 변환할 수 없습니다. 첫 화면에 「변환 엔진 파일이 없습니다」 안내가 뜨면 이 파일이 빠진 것입니다. 깃허브 웹 화면의 끌어 놓기 업로드는 25 MB가 넘는 파일을 받지 않으므로 git 명령이나 다른 방법으로 올리세요. 원본: npm `@ffmpeg/core@0.12.10`의 `dist/umd/ffmpeg-core.wasm`, SHA-256 `9F57947A5BD530D8F00C5B3F2CB2A3492FAA7E5D823315342D6A8656D0A6B7B7`.

## 사용 순서

파일 선택 → 구간 편집 → 형식·용량 선택 → 전후 듣기 → 변환 → 최종 듣기 → 다운로드.

- 원본 A: 처음 불러온 파일의 수정 전 소리.
- 편집본 B: 현재 편집과 보정을 적용한 WAV 미리 듣기.
- 최종 파일: 선택한 형식으로 실제 인코딩된 다운로드 대상. 브라우저 직접 디코딩이 안 되면 로컬 엔진으로 다시 디코딩합니다.
- 파형 선택 시간은 속도·반복·크로스페이드를 적용하기 전의 편집 구간 기준입니다.
- 듣기 음량·확인용 속도·비슷한 음량 비교는 저장에 영향을 주지 않습니다. 확인용 재생 속도는 음높이도 바뀝니다.
- 이 구간 미리 듣기는 현재 선택을 따로 처리하며 반복·여백·배경음은 제외합니다. 전체 혼합 결과는 편집본 B로 확인하세요.

## 제한 및 미구현 세부 항목

- **Opus·WebM 오디오는 모노로만 저장**합니다. 포함된 코어의 libopus는 스테레오를 인코딩할 때 압축 수준 0에서도 잡음이 많은 소리·WebM 담기·60 ms 프레임 등에서 wasm 메모리 오류로 멈추는 것을 확인했습니다(`tests/engine-caps.html#set4`). 모노는 잡음·말소리·5.1 축소·5분 길이·찌그러진 소리까지 모두 통과했습니다. 스테레오가 필요하면 OGG(Vorbis)나 M4A를 쓰세요. Opus 파일을 **열어서** 다른 형식으로 바꾸는 것(입력)은 정상입니다. 샘플레이트는 48 kHz로 고정됩니다.
- 형식별 제한: AC3는 32·44.1·48 kHz와 정해진 비트레이트 단계로, MP2는 16~48 kHz(32 kHz 미만은 160 kbps 이하)로, WMA는 48 kHz 이하로 맞춰 저장하고 결과에 알립니다. M4R은 아이폰 규칙상 40초 이내여야 하며 길면 결과 카드에서 안내만 합니다(잘라 주지 않음). 8비트·32비트 float는 WAV에서만, AIFF·CAF·AU·FLAC·ALAC는 16·24비트입니다. MP3·AAC·Vorbis·Opus·WMA·MP2·영상은 최대 2채널, AC3는 6채널까지입니다.
- **영상 출력**은 브라우저 캔버스로 그린 화면(바탕색·제목·부제목·배경 그림·원본 파형 실루엣)을 PNG로 만들어 엔진에 넘깁니다. 글자 그리기(drawtext)는 코어에 글꼴 파일이 없어 쓰지 않습니다. 정지 화면은 1 fps(60초 720p 기준 약 2초), 파형 애니메이션은 6 fps(60초 720p 기준 약 9초·약 12 MB)로 단일 스레드에서 처리하므로 긴 음원은 시간이 걸립니다. 영상 길이 상한은 음원과 같은 PCM 256 MB 규칙을 따릅니다(48 kHz 스테레오 약 11분). 영상의 소리는 AAC 「fast」 코더(음원 전용 M4A는 기본 코더)로 인코딩합니다. 배경 그림은 작업 설정 JSON에 저장되지 않습니다.
- AMR·GSM은 코어에 인코더가 없어 제공하지 않습니다. 입력은 디코더가 있는 모든 형식(AMR 포함 여부는 파일마다 다름)을 받습니다.
- 모든 파일 확장자가 지원을 보장하지 않습니다. MKV/MOV/MP4 등은 내부 오디오 코덱에 따라 처리됩니다.
- 파일당 최대120 MB, 원본 총용량200 MB, 디코딩/렌더링 PCM256 MB로 제한합니다. 실제 브라우저 메모리 사용량은 더 크며 기기마다 더 낮은 한계가 있을 수 있습니다.
- MP3/AAC/Vorbis에서 원본 다중 채널을 유지할 수 없는 경우 스테레오로 다운믹스하고 결과에 설명합니다.
- 정규화는 -16 LUFS, -1.5 dBTP 목표의 측정 기반 처리입니다. 입력이 -50 LUFS 미만이거나 무음이면 증폭을 건너뛰고 최대 증폭을18 dB로 제한합니다. 리미터 설정은 별도의 샘플 피크 제한입니다. 화면은 실제 LUFS/true peak 수치 분석 대시보드를 제공하지 않습니다.
- 실시간 미터는 듣기 음량을 반영한 채널 RMS 기반 표시입니다. 파형 피크 표시는 원본의 샘플 피크이며 true peak가 아닙니다.
- A/B 시간이 일대일로 연결되지 않는 믹싱·크로스페이드 구간은 처음부터 개별 비교합니다.
- 비트레이트별 짧은 실제 인코딩 비교 전용 기능은 없습니다. 선택 구간을 남긴 뒤 해당 설정으로 변환하여 최종 파일을 비교하세요.
- 구간별 내보내기는 보정·속도만 적용하며 전체 믹스·반복·여백은 제외합니다.
- 일괄 변환·구간별 결과는 하나씩 저장하거나 ZIP 하나로 묶어 저장합니다. ZIP은 압축하지 않고 묶기만 하며(음원은 이미 압축됨), 파일 이름은 UTF-8로 기록합니다. 묶을 결과 합계가 150 MB를 넘으면 하나씩 저장하도록 안내합니다.
- OGG(Vorbis)는 비트레이트 대신 음질 단계(2·4·6·8)를 고릅니다. Vorbis는 샘플레이트·채널마다 허용 비트레이트가 달라 고정 비트레이트 지정이 모노·저샘플레이트 원본에서 실패하기 때문입니다. 화면의 kbps는 44.1 kHz 스테레오 기준 대략값입니다.
- 원본 샘플레이트가 32 kHz 미만(예: 16·22.05 kHz 녹음)이고 MP3를 192 kbps 이상으로 저장할 때, 샘플레이트가 「원본 유지」이면 44.1 kHz로 저장하고 결과에 알립니다. 22.05 kHz를 직접 고르면 MP3 비트레이트는 160 kbps까지만 고를 수 있습니다.
- 거꾸로 재생을 켜면 원본 A와 편집본 B의 시간을 일대일로 맞출 수 없어 처음부터 비교합니다(믹싱과 같음). 채널 처리는 2채널 이상 원본에만 적용되고 다운믹스 전에 처리됩니다.
- 사용자 보정 프리셋은 효과 값만 저장합니다. 전체 편집은 프로젝트 JSON으로 내보내세요. 작업 이력 자체는 JSON에 저장하지 않습니다. 마지막 출력 설정(형식·비트레이트·영상 크기 등, 제목·제작자 태그 제외)은 `localStorage`의 `ss.audio.output`에 기억합니다.
- 프로젝트는 현재 불러온 원본들과 파일명·크기·길이 등으로 비교해 연결합니다. 원본 바이트를 포함하지 않고 해시 기반 재연결은 제공하지 않습니다. 연결이 거부되면 올바른 원본을 다시 선택하세요.
- 원본 커버 이미지는 유지/편집하지 않습니다. 메타데이터 유지 모드는 첫 원본의 텍스트 태그만 대상입니다.
- 브라우저 강제 종료 복구·클라우드 저장·전사·AI 복원은 제공하지 않습니다.
- 2026-10-05 v1.1에서 Windows 11 + Chromium 계열 브라우저로 주요 기능을, v1.2에서 macOS + Claude 앱 내장 브라우저(Chromium)로 새 형식 18가지·영상·채널·역재생을 실제 파일로 검증했습니다(`docs/검증결과.md`). Edge·Firefox·Safari·Android·iOS와 실제 마이크 녹음은 아직 검증하지 않았습니다.

## 단계별 상태

1단계 핵심 변환·추출·편집·3종 재생·저장 흐름을 구현했습니다.
2단계 보정·연결·크로스페이드·취소·실행 취소를 구현했습니다.
3단계 수업 구간·녹음·일괄 변환·태그·설정 저장을 구현했으며 ZIP 음원 묶음·커버·북마크 이름 수정 등은 위 제한을 따릅니다.
4단계 2트랙·덕킹·저장 속도/피치·오프라인 자원을 구현했으며 장치별 호환성 및 최종 통합 검증은 완료 항목으로 표시하지 않습니다.

- OGG에서 고른 비트레이트가 무시되던 문제 → 음질 단계로 변경.
- 손상·무음 영상 등 열 수 없는 파일을 고르거나 불러오기를 취소하면 하던 작업이 모두 사라지던 문제.
- 재인코딩 없는 추출 결과에 적용하지 않은 「리미터」가 표시되던 문제, 편집 요약에서 EQ·컴프레서·페이드 등이 빠지던 문제.
- 창을 열면 입력칸 대신 닫기 단추에 포커스가 가던 문제, 창 안에서 다시 그린 뒤 닫으면 포커스가 사라지던 문제.
- Ctrl/⌘+숫자(브라우저 탭 전환)를 도구 전환 단축키가 가로채던 문제.
- 형식을 바꾸면 비트레이트 값이 목록에 없는 값으로 남던 문제, 결과를 재생할 수 없을 때도 「최종 파일」 단추가 켜지던 문제.
- 비슷한 음량 비교를 켜면 듣기 음량을 움직일 때마다 전체 음원을 다시 계산하던 문제(긴 파일에서 멈춤).
- 북마크 추가·이름 변경이 이미 만든 결과를 「이전 버전」으로 만들던 문제(소리는 그대로이므로).
- 짧은 음원에서 파형 시간 눈금이 같은 숫자로 반복·겹치던 문제, ZIP·녹음 파일 이름 날짜가 UTC 기준이던 문제.
- 프로젝트 설정에 영상의 오디오 트랙 번호가 저장되지 않아 다른 트랙으로 잘못 연결될 수 있던 문제.
- 일괄 변환 실패 줄에 실제 이유 대신 「취소 또는 실패」만 표시되던 문제.

## 개인정보·오프라인

파일과 결과, 원본 파일명·메타데이터는 외부 서비스로 전송하지 않습니다. 외부 API·분석 스크립트·CDN 실행 의존성을 사용하지 않습니다. 로컬스토리지는 테마(`ss.theme`), 직접 저장한 보정 프리셋(`ss.audio.presets`), 마지막 출력 설정(`ss.audio.output`, 제목·제작자 등 내용 태그 제외)만 보관합니다. 원본과 결과, 영상 배경 그림은 메모리에서 다루며 IndexedDB/OPFS/서비스 워커 캐시에 자동 저장하지 않습니다.

도움말의 ‘오프라인 사용 준비’로 정적 실행 자원을 캐시합니다. 모든 자원이 준비된 뒤에만 완료를 표시합니다. 브라우저 캐시 삭제/용량 제한에 따라 다시 준비해야 할 수 있습니다. 자동 업데이트로 작업을 강제 새로고침하지 않습니다. ‘앱 자원 캐시 지우기’는 프로그램 캐시를, ‘작업 데이터 지우기’는 현재 메모리 작업을 정리합니다. 이미 다운로드한 파일을 삭제하거나 기기의 메모리를 보안 소거하는 기능은 아닙니다.

## 개발 구조

- `index.html`, `style.css`, `theme.js`: 화면·주황색 디자인 토큰·테마.
- `app.js`: UI, 재생, 파형, 작업 연결, 녹음·일괄·프로젝트.
- `model.js`: 비파괴 편집 상태, 이력, 시간 매핑, JSON 스키마.
- `engine.js`: 순차 작업 큐, Worker 수명·취소, 원본 재연결.
- `engine-worker.js`: FFmpeg 필터 그래프·분석·인코딩.
- `vendor/`: 고정 엔진·WASM·글꼴·라이선스.
- `sw.js`: 정적 자원만 캐시하는 오프라인 보조 기능.
- `serve.py`: 업로드 기능 없는 정적 파일 서버.
- `tests/engine-caps.html` + `engine-caps.js` + `engine-caps-worker.js`: 번들 코어가 실제로 지원하는 인코더·먹서·필터 목록과 후보 형식의 실제 인코딩 시험(개발용, `#set2` `#set3`로 다른 시험 묶음). 새 형식을 추가하기 전에 여기서 먼저 확인하세요.
- `tests/app-smoke.js` · `tests/app-regression.js`: 앱 화면을 실제로 눌러 보는 전체 점검(21개)과 회귀 점검(18개). 실행 중인 앱 페이지에서 `tests/app-smoke.js`를 불러온 뒤 개발자 도구 콘솔에서 `await runSmoke()` 또는 `await runRegression()`.
- `tests/model-test.cjs`: 편집 모델·엔진 그래프·인코더 옵션 테스트. Node.js가 있으면 `node tests/model-test.cjs`, 없으면 사이트 폴더에서 `python -m http.server 8852 --bind 127.0.0.1`을 실행하고 `http://127.0.0.1:8852/tests/model-test.html`을 엽니다(serve.py의 CSP는 테스트 실행을 막습니다). 제목이 PASS면 통과입니다.
- `archive-v*/`: 각 판 수정 전 원본 백업(배포·저장소에는 필요 없음).
- `docs/영상만들기_예시/`: 실제 앱으로 만든 영상 예시 3개(정지 화면 · 파형 애니메이션 · 세로 쇼츠)와 프레임 그림, 한눈에 보기(`0_영상만들기_한눈에.png`). 배포에는 필요 없음.

효과를 추가하려면 model.js 기본값·검증/직렬화, engine-worker.js 필터·실제 지원 목록, app.js 설정 화면을 함께 확장합니다. 미리 듣기와 최종 출력 모두 공통 그래프를 사용합니다. 출력 형식을 추가할 때는 engine-worker.js `FORMATS`(인코더·먹서·MIME·확장자·kind), `formatOptions`(코덱별 샘플레이트·비트레이트·채널 규칙), model.js `OUTPUT_FORMATS`·`estimateBytes`, app.js `FORMAT_INFO`(이름·설명·갈래·선택지)와 카탈로그 `PAIRS`를 함께 정의하고, `tests/engine-caps.html`로 실제 인코딩을 먼저 확인하세요. 지원하지 않는 항목을 활성화하지 마세요. 출력 설정이나 효과를 바꾸면 결과 버전을 무효화해야 합니다.

## 호스팅 설정

Worker/JS MIME은 `text/javascript`, WASM은 `application/wasm`, WOFF2는 `font/woff2`로 제공합니다. HTTPS를 사용하면 마이크와 서비스 워커를 사용할 수 있습니다. 현재 단일 스레드 엔진은 SharedArrayBuffer 및 COOP/COEP가 필수가 아닙니다. 향후 다중 스레드를 추가할 경우 `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`와 `crossOriginIsolated`를 확인해야 합니다.

CSP 예시는 serve.py에 포함되어 있습니다. script-src에는 self 및 wasm-unsafe-eval, worker-src에는 self/blob, media-src에는 self/blob가 필요합니다. 앱 수정 시 sw.js의 VERSION을 갱신해 엔진·앱 버전이 섞이지 않게 유지하세요.
